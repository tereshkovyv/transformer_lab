# DeepSeek-V3: архитектура и основные компоненты

## 1. Основа архитектуры DeepSeek-V3

Архитектура DeepSeek-V3 основана на трёх ключевых компонентах:

- **Multi-Head Latent Attention (MLA)** — механизм внимания, который сокращает затраты памяти на хранение KV-cache во время генерации текста.
- **DeepSeekMoE** — архитектура Mixture of Experts (MoE), позволяющая активировать только часть параметров модели для обработки каждого токена.
- **Multi-Token Prediction (MTP)** — дополнительная обучающая задача, при которой модель учится предсказывать несколько следующих токенов, а не только один.

Модель содержит **671 млрд параметров, из которых для обработки каждого токена активируется около 37 млрд**.

### 1.1. Общая структура Transformer-блока

В упрощённом виде модель состоит из множества последовательно расположенных Transformer-блоков.

В каждом блоке есть два основных вычислительных компонента:

1. **Attention (MLA)** — позволяет токенам учитывать информацию из предыдущих токенов последовательности.
2. **Feed-Forward Network (FFN/MoE)** — преобразует представления токенов с помощью нейронных сетей.

Между компонентами используются нормализация RMSNorm и остаточные соединения (residual connections).

### 1.2. Общая схема обработки текста

```text
Входной текст
     ↓
Токенизация
     ↓
Представления токенов (Embeddings)
     ↓
┌──────────────────────────────┐
│       Transformer-блок       │
│                              │
│  RMSNorm                     │
│     ↓                        │
│  MLA (Attention)             │
│     ↓                        │
│  Residual Connection         │
│     ↓                        │
│  RMSNorm                     │
│     ↓                        │
│  DeepSeekMoE                 │
│     ↓                        │
│  Residual Connection         │
└──────────────────────────────┘
     ↓
Повторение блоков
     ↓
Выходные представления
     ↓
Логиты → Softmax
     ↓
Распределение вероятностей
     ↓
Предсказание следующего токена
```

4\. Transformer-блок — основная часть модели, которая обрабатывает информацию:

- RMSNorm — нормализует данные, чтобы сделать вычисления стабильнее.
- MLA (Attention) — определяет, какие токены важны друг для друга в контексте, и учитывает связи между ними.
- Residual Connection — добавляет исходную информацию к результату обработки, чтобы не терять её.
- RMSNorm — повторно нормализует данные перед следующим этапом.
- DeepSeekMoE — направляет каждый токен к нужным экспертам, которые обрабатывают информацию.
- Residual Connection — снова сохраняет исходную информацию, добавляя её к результату обработки.

5\. Повторение блоков — информация проходит через множество Transformer-блоков.

6\. Выходные представления — итоговые числовые представления токенов после обработки всеми блоками.

7\. Логиты - Softmax — модель рассчитывает оценки возможных следующих токенов и преобразует их в вероятности.

## 2. Multi-Head Latent Attention (MLA)

**MLA — это модифицированный механизм внимания, который сокращает объём памяти, необходимый для хранения Key-Value Cache во время генерации текста.**

Обычный механизм внимания использует три представления каждого токена:

- **Query (Q)** — какую информацию ищет текущий токен.
- **Key (K)** — по каким признакам другие токены могут быть найдены.
- **Value (V)** — какую информацию токены передают при взаимодействии.

### 2.1. Как работает механизм внимания?

В упрощённом виде процесс выглядит так:

1. Модель вычисляет Query для текущего токена.
2. Сравнивает его с Key предыдущих токенов.
3. Преобразует результаты сравнений в веса внимания с помощью Softmax.
4. Использует полученные веса для взвешенной суммы Value.
5. Передаёт результат дальше по сети.

В обычном Multi-Head Attention (MHA) используются несколько голов внимания. Каждая голова имеет собственные проекции Q, K и V и может учиться учитывать разные аспекты контекста.

### 2.2. Что такое KV-cache и почему он занимает много памяти?

При авторегрессионной генерации модель выдаёт текст по одному токену за раз.

Пример последовательной генерации:

```text
Шаг 1: The
Шаг 2: The cat
Шаг 3: The cat sat
Шаг 4: The cat sat down
```

На каждом шаге модели необходимо учитывать предыдущие токены.

Если каждый раз заново вычислять Key и Value для всей последовательности, это приведёт к повторным вычислениям.

Для ускорения генерации модель сохраняет уже вычисленные Key и Value в специальной памяти — **KV-cache**.

На следующем шаге она вычисляет представления нового токена и использует ранее сохранённые значения.

Однако с увеличением длины контекста растёт объём KV-cache. В большой модели с множеством слоёв и голов внимания это может стать серьёзным ограничением.

### 2.3. Как MLA решает эту проблему?

Вместо того чтобы сохранять полные Key и Value для каждой головы внимания, MLA **совместно сжимает информацию, необходимую для их формирования, в компактное латентное представление**.

Это ключевая идея MLA, описанная в разделе 2.1.1 статьи.

#### Схема сжатия Key-Value представлений

```text
Входное представление токена h
              ↓
      Сжатие (Down-Projection)
              ↓
      Компактный латентный
         вектор c_KV
              ↓
        ┌─────┴─────┐
        ↓           ↓
 Восстановление  Восстановление
      Key             Value
        ↓           ↓
 Key для голов   Value для голов
   внимания         внимания
```

## 3. DeepSeekMoE

**DeepSeekMoE — это архитектура Mixture of Experts (MoE), в которой для обработки каждого токена выбираются только некоторые нейронные сети-эксперты.**

Основная идея заключается в том, чтобы увеличить общую ёмкость модели, не активируя все её параметры при обработке каждого токена.

### 3.1. Что такое Mixture of Experts?

В обычном Transformer-блоке FFN (Feed-Forward Network) обрабатывает представление каждого токена.

В архитектуре MoE вместо одной общей FFN используется несколько специализированных сетей — **экспертов (Experts)**.

#### Схема работы MoE

```text
                  Входной токен
                        ↓
                      Router
                        ↓
             Выбор подходящих экспертов
                        ↓
              ┌─────────┼─────────┐
              ↓         ↓         ↓
          Эксперт 1  Эксперт 2  Эксперт 3
              ↓         ↓         ↓
              └─────────┼─────────┘
                        ↓
               Объединение выходов
                        ↓
                Выходное представление
```

**Router (маршрутизатор)** определяет, какие эксперты будут обрабатывать конкретный токен.

DeepSeekMoE использует две важные идеи.

#### 1. Fine-grained Experts — большое количество небольших экспертов

Вместо небольшого количества крупных экспертов используются многочисленные более мелкие эксперты, из которых маршрутизатор выбирает ограниченное число.

Это позволяет гибче комбинировать экспертов для обработки разных токенов.

#### 2. Shared Experts — общие эксперты

Помимо выбираемых маршрутизатором экспертов, существуют общие эксперты, которые активируются для каждого токена в соответствующем MoE-слое.

Их назначение — обрабатывать знания и закономерности, которые полезны для многих токенов, уменьшая необходимость повторять одинаковые функции во множестве маршрутизируемых экспертов.

## 4. Auxiliary-loss-free load balancing (Разделы 2.1.2 и 4.5)

**Auxiliary-loss-free load balancing** — это метод, который регулирует распределение токенов между экспертами с помощью изменения их `bias`. В отличие от традиционного подхода, он не использует дополнительную функцию потерь для балансировки, что помогает поддерживать равномерную нагрузку без лишнего влияния на качество модели.

В архитектуре есть много экспертов, и Router (маршрутизатор) выбирает, какие из них будут обрабатывать каждый токен. Проблема заключается в том, что Router может слишком часто направлять токены к одним и тем же экспертам, а остальных использовать редко.
В результате:

- Одни эксперты получают слишком много работы, а другие практически простаивают.
- Нагрузка между GPU распределяется неравномерно.
- Обработка токенов может замедляться из-за перегруженных экспертов.
### Главное преимущество метода

Можно балансировать нагрузку между экспертами, не добавляя дополнительную функцию потерь, которая может отрицательно влиять на качество модели.

### Как авторы решают проблему?

Обычно для балансировки экспертов используют дополнительную функцию потерь, которая во время обучения штрафует модель, если она слишком часто выбирает одних экспертов и редко — других. Но у подхода есть недостаток: стремление равномерно распределять токены может мешать модели выбирать наиболее подходящих экспертов и тем самым ухудшать качество обучения.

В DeepSeek-V3 используется другой подход:

1. Система отслеживает, сколько токенов получает каждый эксперт.
2. Если какой-то эксперт получает слишком много токенов, его показатель смещения (`bias`) уменьшается.
3. Если эксперт используется слишком редко, его `bias` увеличивается.
4. При следующем выборе Router учитывает эти изменения и корректирует распределение токенов между экспертами.

Что такое bias? Это дополнительное значение, которое влияет на оценку эксперта при выборе маршрутизатора. Например:

- **Эксперт 1 слишком загружен** — его `bias` уменьшается, поэтому выбирать его становится менее выгодно.
- **Эксперт 2 используется редко** — его `bias` увеличивается, поэтому вероятность его выбора повышается.

## 5. Multi-Token Prediction (MTP) Раздел 2.2 Multi-Token Prediction, стр. 10

**Multi-Token Prediction — это обучающая задача, при которой модель обучается предсказывать не только следующий токен, но и несколько последующих токенов.**

В DeepSeek-V3 дополнительные токены предсказываются последовательно с помощью отдельных MTP-модулей. При этом сохраняется причинная зависимость между этапами предсказания.
В реализации DeepSeek-V3 используются общие слои эмбеддингов и выходная голова, а также отдельный Transformer-блок и матрица проекции для каждого дополнительного этапа MTP.
```text
Входная последовательность
          |
          v
  Основная Transformer-модель
          |
          v
  Скрытые представления
          |
          +----------------------+
          |                      |
          v                      v
 Предсказание x(i+1)       MTP-модуль 1
                                 |
                                 v
                       Предсказание x(i+2)
                                 |
                                 v
                       MTP-модуль 2
                                 |
                                 v
                       Предсказание x(i+3)
```
На каждом дополнительном шаге MTP объединяет две части информации: скрытое представление, полученное на предыдущем этапе, эмбеддинг соответствующего будущего токена из обучающих данных.

MTP использует:

- Представление токена, полученное основной моделью.
- Embedding следующего целевого токена.
- Дополнительный Transformer-блок.
- Выходной слой для предсказания токена.

### Преимущества MTP

1. **Улучшение качества обучения** — дополнительная задача предсказания помогает модели лучше изучать зависимости между токенами.
2. **Более эффективное использование обучающих данных** — модель получает дополнительный сигнал обучения, предсказывая несколько последующих токенов.
3. **Возможность ускорения генерации текста** — MTP можно использовать совместно с методом Speculative Decoding.

MTP можно использовать совместно с методом Speculative Decoding. В этом случае модель заранее предлагает дополнительный токен, а основная модель проверяет его правильность. Если предсказание принимается, не нужно тратить отдельный последовательный шаг на его генерацию.

**Speculative Decoding (спекулятивное декодирование)** — метод ускорения генерации текста, при котором небольшая и быстрая модель заранее предлагает несколько следующих токенов, а основная большая модель параллельно проверяет их правильность. Если предложенные токены подходят, они принимаются сразу, чтобы генерировать несколько токенов за один шаг вместо последовательной генерации каждого токена.
