# Гипотезы


## Efficient Attention


**Направление:**

Efficient Attention


**Определение:**

Главный вопрос: как уменьшить вычислительную стоимость attention, особенно при работе с длинными последовательностями?

При увеличении длины последовательности вычисления становятся дорогими.

Что пытаются улучшить: сам способ вычисления внимания, его вычислительную сложность, потребление памяти или скорость обработки последовательностей.  


**Методы решения:**

1. алгоритмы эффективного внимания;
2. методы разреженного внимания;
3. методы приближённого внимания;
4. алгоритмы, уменьшающие объём промежуточных данных.


**Фундаментальные работы:**

X-former Elucidator: Reviving Efficient Attention for Long Context Language Modeling, 2024, https://ijcai.org/proceedings/2024/904


**Ключевая (фундаментальная) работа  — Название и ссылка:**

1. FlashAttention-4: Algorithm and Kernel Pipelining Co-Design for Asymmetric Hardware Scaling (https://arxiv.org/abs/2603.05451) 2026

2. Scaling Context Requires Rethinking Attention (https://arxiv.org/abs/2507.04239) 2025

**Репозиторий:**

1. https://github.com/Dao-AILab/flash-attention/tree/main/flash_attn/cute

2. https://github.com/m-a-n-i-f-e-s-t/power-attention

**Метод:**

1. Основной метод — конвейерное выполнение операций (pipelining): вычисления матричных произведений, Softmax и загрузка данных организуются так, чтобы выполняться параллельно, насколько это возможно.
Дополнительно авторы ускоряют Softmax, приближённо вычисляя экспоненту на других вычислительных блоках GPU, и сокращают лишние операции нормализации; при обратном проходе уменьшают обмен данными через shared memory.  

2. используют Power Attention — модификацию линейного. Чтобы не допустить роста вычислений и памяти, используют symmetric power — позволяет уменьшить количество избыточных компонентов внутреннего представления. 


**Суть:**

1. FlashAttention-4 — оптимизирует вычисление attention на уровне GPU. Главное: уменьшить простои и ускорить вычисления.

2. Power Attention — изменяет сам механизм внимания, используя модификацию линейного attention. Главное: эффективнее обрабатывать длинные последовательности


**Гипотезы — Формулировка:**

Применение методов Efficient Attention, направленных на оптимизацию вычислений на GPU (FlashAttention-4) и изменение математической формы механизма внимания (Power Attention),  позволяет снизить время инференса и вычислительные затраты при обработке длинных последовательностей без существенного ухудшения качества генерации текста.


**Обоснование:**

Что мы оптимизируем: время инференса, потребление GPU-памяти, качество модели.
За счёт чего: FlashAttention-4 (оптимизация выполнения операций на GPU), Power Attention (изменение мат. формы механизма внимания) 
Что измеряем:  время инференса, использование GPU-памяти и качество модели.
Как проверяем: сравниваем оптимизированную реализацию с базовой при одинаковых модели, входных данных и условиях эксперимента.


## KV-cache optimization


**Направление:**

KV-cache optimization


**Определение:**

Главный вопрос: как уменьшить память, необходимую для авторегрессионной генерации текста?

При генерации Transformer последовательно создаёт новые токены. Чтобы каждый раз не вычислять ключи и значения для всей предыдущей последовательности заново, модель сохраняет их в KV-cache. Без кэша ей пришлось бы повторно вычислять некоторые представления предыдущих токенов. С кэшем сохранённые ключи и значения можно использовать повторно.


**Методы решения:**

1. уменьшать размер хранимых данных;
2. сокращать количество сохраняемых токенов;
3. использовать более компактные представления ключей и значений;
4. эффективнее размещать кэш в памяти.


**Фундаментальные работы:**

A Survey on Large Language Model Acceleration based on KV Cache Management, 2025

Авторы: Haoyang Li, Yiming Li, Anxin Tian и соавторы

https://arxiv.org/pdf/2412.19442

**Ключевая (фундаментальная) работа  — Название и ссылка:**

1. GQLA: Group-Query Latent Attention for Hardware-Adaptive Large Language Model Decoding https://arxiv.org/abs/2605.15250

2. HqeKV: Towards Hybrid Quantization and Eviction for KV Cache in Long-Context LLM Inference https://aclanthology.org/2026.findings-acl.201/

**Репозиторий:**

1. https://github.com/MuLabPKU/TransArch

2. https://github.com/skywclouds/HqeKV


**Метод:**

1. GQLA (Group-Query Latent Attention) — модификацию MLA, которая позволяет использовать одни и те же веса модели. 
- MQA-absorb, хранит компактное латентное представление ключей и значений, уменьшая объём KV-cache,
- GQA, восстанавливает отдельные представления ключей и значений 

2. HqeKV — гибридный подход, который объединяет способы сжатия и выбирает подходящий вариант для каждой пары Key–Value в зависимости от её важности. Самые важные данные хранятся с высокой точностью, менее важные — с пониженной, а наименее в-е полностью удаляются из кеша. Для определения важности авторы разработали совместную метрику для Key и Value


**Суть:**

1. GQLA — сокращает объём KV-cache за счёт компактного латентного представления Key и Value

2. HqeKV — сокращает объём KV-cache за счёт адаптивного сжатия и удаления данных в зависимости от их важности.


**Гипотезы — Формулировка:**

Сочетание методов 1. компактного латентного представления Key и Value с 2. адаптивным квантованием и удалением менее важных элементов KV-cache позволит уменьшить потребление памяти Transformer и вычислительные затраты при обработке длинных последовательностей без существенного ухудшения качества генерации текста.


**Обоснование:**

Что оптимизируем: объем памяти, занимаемый KV-cache
За счёт чего: компактное представление Key и Value и адаптивное квантование и удаление 
Что измеряем:  время инференса, использование GPU-памяти и качество модели.
Как проверяем: сравниваем оптимизированную реализацию с базовой при одинаковых модели, входных данных и условиях эксперимента.


## Attention sparsity / compression


**Направление:**

Attention sparsity / compression


**Определение:**

Главный вопрос: обязательно ли учитывать все токены и всю информацию в контексте?

В стандартном attention каждый токен может учитывать все доступные ему токены с учётом маскирования.


**Методы решения:**

1. Разреженное внимание (Sparse Attention) - модель вычисляет внимание только для определённых пар токенов.
Например:
- ближайшие к нему токены;
- отдельные специальные токены;
- выбранные токены, которые считаются важными.

2. Сжатие контекста (Context Compression) - модель сокращает представление исходного контекста, например удаляя, объединяя или сжимая часть информации.

Различие: sparse attention ограничивает набор вычисляемых связей, а compression сокращает или уплотняет представление информации.

**Фундаментальные работы:**

A Practical Survey on Faster and Lighter Transformers, 2023
https://dl.acm.org/doi/10.1145/3586074

**Ключевая (фундаментальная) работа  — Название и ссылка:**

1. Block Sparse Flash Attention https://arxiv.org/abs/2512.07011

2. SparDA: Sparse Decoupled Attention for Efficient Long-Context LLM Inference https://arxiv.org/abs/2606.04511

3. The Sparse Frontier: Sparse Attention Trade-offs in Transformer LLMs https://arxiv.org/pdf/2504.17768

**Репозиторий:**

1. https://github.com/Danielohayon/Block-Sparse-Flash-Attention

2. https://github.com/NVlabs/SparDA/tree/main

3. https://github.com/PiotrNawrot/sparse-frontier

**Метод:**

1. разреженное внимание на уровне блоков: последовательность разбивается на блоки, и модель определяет, какие из них наиболее важны для текущего внимания.  Для этого вычисляем точные оценки сходства между Query и Key, и сравнивает максимальную оценку каждого блока с настроенным порогом;    

2. SparDA добавляет к стандартным Q, K и V четвёртую проекцию — Forecast, которая заранее предсказывает, какие блоки KV-cache понадобятся следующему слою.  загрузка нужных данных на GPU может происходить параллельно с вычислениями текущего слоя

3. Авторы сравнивают 6 методов Sparse Attention, которые позволяют вычислять внимание только между выбранными токенами или блоками токенов, не требуя дополнительного обучения модели.   


**Суть:**

1. Отбирает блоки для вычисления внимания, чтобы сократить объём ненужных вычислений.

2. Использует прогнозирование необходимых блоков KV-cache и параллельную загрузку данных для ускорения инференса.


**Гипотезы — Формулировка:**

Применение методов Sparse Attention, ограничивающих вычисления наиболее релевантными токенами или блоками токенов, позволяет снизить время инференса и вычислительные затраты при обработке длинных последовательностей без существенного ухудшения качества генерации текста.


**Обоснование:**

Что оптимизируем: вычислительную стоимость, использование памяти и время инференса.
За счёт чего: пропускаем менее важные блоки при вычислении внимания и прогнозируем необходимые блоки KV-cache для ускорения доступа к данным.
Что измеряем:  время инференса, использование GPU-памяти и качество модели.
Как проверяем: сравниваем оптимизированную реализацию с базовой при одинаковых модели, входных данных и условиях эксперимента.

## Kernel-level optimization


**Направление:**

Kernel-level optimization


**Определение:**

Главный вопрос: как быстрее и экономнее выполнить вычисления на оборудовании, которое у нас уже есть?


**Методы решения:**

Например на GPU:
- уменьшить количество обращений к видеопамяти;
- объединить несколько операций в один GPU kernel;
- не сохранять целиком промежуточную матрицу внимания;
- эффективнее использовать быструю память GPU;
- лучше организовать параллельные вычисления.


**Фундаментальные работы:**

FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness, 2022
Авторы: Tri Dao, Daniel Y. Fu, Stefano Ermon, Atri Rudra, Christopher Ré.
https://arxiv.org/pdf/2205.14135

**Ключевая (фундаментальная) работа  — Название и ссылка:**

1. FlashInfer: Efficient and Customizable Attention Engine for LLM Inference Serving https://arxiv.org/abs/2501.01005


**Репозиторий:**

2. https://github.com/flashinfer-ai/flashinfer


**Метод:**

использует JIT-компиляцию, позволяет адаптировать вычислительные ядра Attention под конкретные задачи и оборудование. Дополнительно применяется динамическое распределение вычислений между GPU.


**Суть:**

Оптимизирует GPU-ядра вычисления Attention с помощью настраиваемых шаблонов, JIT-компиляции и планирования вычислений.


**Гипотезы — Формулировка:**

Применение оптимизированных GPU-ядер для вычисления Attention с использованием JIT-компиляции и адаптивного планирования вычислений позволит сократить время инференса и повысить эффективность использования GPU-памяти при обработке длинных последовательностей без существенного ухудшения качества генерации текста.


**Обоснование:**

Что оптимизируем: выполнение операций Attention на GPU.
За счёт чего: настройки вычислительных ядер под оборудование и задачи, JIT-компиляции и планирования вычислений.
Что измеряем: время инференса, использование GPU-памяти и качество модели.
Как проверяем: сравниваем оптимизированную реализацию с базовой при одинаковых модели, входных данных и условиях эксперимента.
